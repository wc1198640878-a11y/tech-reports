# WH3 自动指挥 Mod —— 设计文档

## 1. 目标

- 单机战斗内**全自动托管玩家全军**（不碰战役大地图）
- 不仅打赢，而是**以最小伤亡打赢**
- 野战与攻城战分别处理（两者的 AI 机制不同）
- 完全自用，不发布、不联机；游戏版本已锁定

## 2. 技术路线

**原生战斗 AI 打底 + Lua 规则层微调**：

| 层 | 机制 | 用途 |
|----|------|------|
| 底层 | `script_ai_planner` / `ai_planner`（原生 AI 组） | 把单位分组交给游戏自带 AI，下达高层命令（防御点/进攻部队），单位在半自主模式下自行应对威胁 |
| 规则层 | Lua 脚本轮询（`bm:repeat_callback` / watch）+ `script_unit` 查询与指令 | 分队编组、目标优先级、预备队投入、骑兵包抄循环冲锋、受损单位后撤、法术释放时机 |
| 状态查询 | `script_unit`（.unit 查状态：unary_hitpoints、is_in_melee、士气等；.uc 下指令） | 规则层决策依据 |

## 3. 关键 API 摘要（来自官方脚本文档）

- 脚本库：`load_script_libraries()` 之后自动有全局 `bm`（battle_manager）
- 全军对象：
  - `bm:get_scriptunits_for_local_players_army()` → 玩家全军 script_units 集合
  - `bm:get_scriptunits_for_main_enemy_army_to_local_player()` → 敌方主军
  - `bm:get_player_alliance_num()` / `bm:get_non_player_alliance_num()`
- 战场阶段：`bm:register_phase_change_callback("Deployed", fn)`；阶段有 Deployment / Deployed / VictoryCountdown / Complete
- 计时轮询：`bm:repeat_callback(fn, ms, "name")`（战斗内单位是毫秒）
- AI 组：
  - `script_ai_planner:new(name, sunits[, debug])` → planner
  - 命令：`move_to_position` / `defend_position(pos, radius)` / `attack_force(enemy_sunits)` / `rush_force` / `patrol`
  - `add_sunits` / `remove_sunits` / `release`（释放回玩家）
  - 注意：**官方文档明确警告攻城战中不要用 ai planner**（攻城 AI 会覆盖单位行为）
- 单兵命令（规则层）：`sunit.uc:goto_location_angle_width(pos, deg, width, fast)`、`attack_unit`、`halt`、`change_behaviour_active("fire_at_will"/"skirmish"/...)`、`perform_special_ability(key, target)`
- 单兵状态：`sunit.unit:unary_hitpoints()`、`sunit:is_in_melee()`、`sunit:is_under_attack()`、`sunit:has_taken_casualties()` 等

## 4. 野战架构（v2 目标）

全军按职能编组，各建一个 script_ai_planner（或部分由规则层直控）：

1. **接战线**（前排步兵/近战）：planner defend_position 于推进线 → 接敌后 attack_force 敌步兵群
2. **预备队**（次优近战）：held 于中线后方，规则层判断投入时机（接战线某段崩溃/敌方主力全部投入时）
3. **远程/炮兵**：部署于后排高处，fire_at_will；规则层做目标聚焦（优先敌方领主/巨兽/高价值单位）
4. **骑兵/机动**：规则层直控或独立 planner——绕侧、循环冲锋（冲→脱战→再冲）、追溃、救火（拦截敌方骑兵）
5. **领主/法师**：规则层控制走位 + 法术时机（敌方密集区放大杀伤法术）

规则层职责（最小损失导向）：
- 接战前不急于全线冲锋：先用远程/炮火磨敌方血量
- 受损单位后撤轮换（unary_hitpoints < 阈值 → 撤回预备队换人）
- 反大型/反骑兵单位盯防对应威胁，不参与正面绞肉
- 追击溃兵有限度：防止被拖散阵型、防止撞进敌方援军
- 骑兵冲锋后强制脱离再冲锋（cycle charge）

## 5. 攻城战架构（v3 目标）

- **禁用 ai planner**（官方警告）
- 优先方案：整军移交给游戏原生攻城 AI（AI General 的做法——待拆包确认具体 API），规则层只做：
  - 攻方：选择突破点、攻城器械攻击目标序列（先破城门/墙段）、占领点优先级
  - 守方：城墙兵力分配、弃墙退守判定、反登城预备队
- 待确认的 API：是否存在 `army:set_ai_active` 之类整军移交接口；否则用 per-unit 移交（AI General 的 ai_list 机制）

### 5.1 实测教训（v1.1 攻城战，20v20 settlement_standard）

- SIEGE_SAFE（纯移交、不下目标）在攻城**攻击**中打输：12 分钟消耗战，单位 20→13 逐个战损后 Complete（无 VictoryCountdown = 战败）
- 待查：军队行为（卡墙下挨打 vs 正常攻打不过）——v1.5 加了 melee/moving/idle/enemy_alive 诊断
- v1.5 准备：`siege_attack_objective` 实验开关（攻城攻击也下 attack_force + force_ai_plan_type_attack，配释放盾覆盖攻城），默认关；诊断数据决定是否启用

## 6. 托管开关（v1）

- 进战斗（Deployed 阶段）自动全托管
- UI 按钮（AI 开/关）后续加（uicomponent + battle_ui_manager）

## 7. 已确认事实（更新于 v0 阶段）

- [x] mod 战斗脚本自动加载机制：**`script/battle/mod/*.lua` 全自动加载**（AI General III 参考 mod 即此结构，实证）

- [x] 攻城战：参考 mod 用 `bm:is_siege_battle()` / `bm:battle_type()` 检测（land_normal / land_ambush / unfortified 等），攻城时清空野战目标、把单位交给原生攻城 AI 自行发挥
- [x] 战斗事件不常用，官方推荐轮询（bm:repeat_callback / watch）
- [x] 工具链：RPFM v4.7.4 CLI（v5 无 CLI）；打包命令 pack create + pack add -f "file;dir/"
- [x] 调试：游戏 data\script\ 下建 enable_console_logging 空文件 → 脚本输出落盘（实测：游戏根目录 script_log_*.txt）
- [x] **端到端实测（2026-09-28）**：v0 包在用户战斗日志中出现完整阶段序列（loaded ok → Deployment → Deployed → VictoryCountdown → Complete），mod 加载、战斗脚本自动执行、阶段回调、日志输出全部验证通过
- [x] 工具链补充：luaparse（Node）做 Lua 5.1 语法检查，已接入 build.ps1
- [x] 关键坑（参考 mod 报告）：CA wrapper（attack_force 等）会调 ensure_units_are_released 把玩家军队控制权还给玩家 → 全军僵死；v1.1 已带释放盾（运行时包装压制）
