## 走过的两条路，以及各自失败在哪

### 路线 A：UE4SS + Lua mod（我自己写的 AutoDodgeMod）

失败原因**已用 dump 实证**，不是猜的：

| 构建 | 结果 | 证据 |
|---|---|---|
| 稳定版 v3.0.1 | `UE4SS.dll` 内部空指针崩溃 | `crash_*.dmp`：`0xc0000005` 参数=0，故障模块 `UE4SS.dll+0x4baaaf` / `+0x4bddae`。**`nomod` 档（零 mod）照样崩** |
| experimental #1152 | detour 装不上 + 标题界面闪退 | 日志 `Potentially customized vtables`、`Failed to add hook, detour installation likely failed!` ×7 |

**根因**：UE4SS 的特征码扫描对不上这个可执行文件。

> 中途我犯过一个错：拿"60 天零崩溃"当证据推断是 UE4SS，但存档显示那段时间
> 用户根本没玩过游戏（上次游玩 2025-12-15）。那个推论当时是错的，
> 后来靠 `nomod` 二分 + dump 解析才真正证实。

### 路线 B：CSharpLoader + Harmony（你下载的 PerfectDodgeV2.4）

**加载器完全正常**，这个已经证实：

```
[D] Found ICSharpMod: PerfectDodgeV2.PerfectDodgeMod
[PerfectDodgeV2.4] PerfectDodgeV2.4 initialized successfully.   <- PatchAll 成功
[PerfectDodgeV2.4] Config loaded: ExtendedWindowSeconds=1, AutoDodgeOnAttack=True, ...
CSharpLoader init success.
```

6 个 Harmony 补丁全部挂载成功，配置也读到了。**但运行期毫无反应。**

**诊断 mod 找到了关键事实**：挂钩 `BtlSvr.Main` 里 **374 个** `OnTickWithGroup`
（该程序集共 590 个），用户实际进入游戏世界玩了 4.5 分钟（有实时存档备份为证），
**一个都没触发**；连挨打必调的 `BUS_BeAttackedComp:OnHandleNormalDamageEffect` 也是 0。

ECS tick 是游戏每帧的命脉，全 0 只有一个解释：
**`BtlSvr.Main` 里的这套 tick 不是实际执行的那套代码。**

原 mod 的单点故障正在这里——它的 `IsInGame` 只在这一个 tick 补丁里被置位，
其余 5 个补丁开头全是 `if (!IsInGame) return;`。**这一环不触发，整个 mod 静默空转。**

推测正确方向是 **`b1.Managed`**（客户端逻辑）而非 `BtlSvr.Main`（Battle Server），
但 v1.2.0 的跨程序集扫描（挂钩 500 个方法）**导致游戏闪退**，没能取到那次结果。

## 原 mod 已知的真实 bug

1. **配置解析错误**：`config.json` 写 `"AlwaysPerfectDodge": true`，
   控制台加载出来是 `False`。
2. **单点故障**：`IsInGame` 唯一置位点在 `BPS_PlayerInteractComp:OnTickWithGroup`。
3. **全静默**：所有 `catch` 都是空的，任何一环断掉都无提示。
