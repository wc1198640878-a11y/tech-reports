# 自动闪避 Mod — 最终交付说明

**日期**：2026-09-30
**状态**：**能用，但不稳定** —— 大约每 4–6 次启动能成功一次。

---

## 一、现在装了什么

```
E:\...\b1\Binaries\Win64\
    version.dll                    ← 你下载的 CSharpLoader（注入代理）
    CSharpLoader\
        Mods\
            PerfectDodgeV2.4\      ← 你下载的 mod（原样，未修改）
            ADFix\                 ← 我写的辅助 mod
```

**ADFix 做三件事：**

1. **持续把 `IsInGame` 置为 true** —— 原 mod 的致命单点故障：
   ```csharp
   IsInGame = true;      // 全文唯一置位处，在一个时灵时不灵的 tick 里
   // 其余 5 个补丁开头全是：if (!IsInGame) return;
   ```
2. **最多重打 6 轮补丁 + 重调一次 `PerfectDodgeMod.Init()`** —— 试图绕开"启动瞬间打不上补丁"的问题
3. **给出明确判定** —— 启动后约 2.5 分钟在日志里写 ✅ / ❌

**怎么样用：**

```powershell
# 启动游戏后等 3 分钟，看判定
Get-Content 'E:\...\Win64\CSharpLoader\Mods\ADFix\adfix.log' -Tail 12
```

| 判定 | 做法 |
|---|---|
| ✅ 补丁已进调用链 | 正常玩，mod 完全生效 |
| ❌ 补丁未进调用链 | **退出游戏重开**，再看一次判定。抽到 ✅ 为止 |

**卸载：** 删掉 `CSharpLoader\Mods\ADFix\` 即可，其他什么都不用动。

---

## 二、三个功能怎么用

`I` 键（大键盘）在两种模式间切换，**没有任何提示**，用"角色会不会自己闪"来判断：

| 模式 | `AutoDodgeOnAttack` | `AlwaysPerfectDodge` | 表现 |
|---|---|---|---|
| **I 开** | True | False | 角色被攻击时**自己闪**；手动闪避不保证完美 |
| **I 关** | False | True | 不自动闪；**手动怎么闪都是完美闪避** |

**这两个功能在原 mod 里是互斥的**（第 151 行 `AlwaysPerfectDodge = !AutoDodgeOnAttack && ...`，加上热键里的互斥赋值）。想要"两个同时开"需要改代码。

**其他参数**（`CSharpLoader\Mods\PerfectDodgeV2.4\config.json`，改完直接生效）：

| 项 | 当前 | 说明 |
|---|---|---|
| `ExtendedWindowMilliseconds` | 1000 | 完美闪避判定窗口。原版 **180ms**，这个值放宽到 1 秒 |
| `ExcludeForwardDodge` | true | 自动闪避只左右后，不往前 |
| `ToggleAutoDodgeHotkey` | "I" | 切换热键 |

## 三、为什么不稳定（这是核心结论）

**Harmony 补丁能不能进调用链，不受我们控制。**

实测数据：

| 会话 | 补丁时机 | 探针命中 | 结果 |
|---|---|---|---|
| 23:53 | 启动瞬间 | **16,602,969** | ✅ 成功 |
| 00:02 / 00:11 / 00:14 | 启动瞬间 | 0 | ❌ |
| 00:23 | 启动瞬间 | 0 | ❌ |
| 00:34 | 启动瞬间 + 31 秒后补打 | **40,976** | ✅ 成功 |
| 00:42 | 启动瞬间 + 31 秒后补打 | 0 | ❌ |
| 00:46 | 启动瞬间 + **6 轮重打**（到 2.5 分钟） | 0 | ❌ |

**同样的配置、同样的时机、同样的代码，结果随机。** 换过 UE4SS 两个官方构建、换过打补丁的时机、加过重试——都不解决。

**推测的机制**（未证实）：Harmony 改的是方法的**机器码入口**。如果调用方被 JIT 内联了那份代码，改入口对副本无效。是否内联取决于运行时的判断，而这个判断在本机表现为随机。

**同类现象**：我自己写的 Harmony 自检也一直失败（目标方法太短被内联），加了 `NoInlining` 才正常——**这从侧面印证了内联确实是这里的核心障碍**。

## 四、走过的三条路，以及各自死在哪

### 方案一：UE4SS + Lua（我最早写的 AutoDodgeMod）

**死于 UE4SS 与这个游戏不兼容。**

- 稳定版 v3.0.1：`UE4SS.dll` 内部空指针崩溃（dump 实证 `0xc0000005`，`nomod` 档零 mod 照样崩）
- experimental #1152：`Potentially customized vtables`，7 个 detour 装不上

**根本原因**：游科大幅改造了引擎（几百个 `GS*` 自研插件），而 **UE4SS 的"按游戏定制配置"里根本没有黑猴**（只有 14 个别的游戏）。没人给它做过特征码适配。

### 方案二：配置文件 cvar

**完全没反应。** 我从 exe 里挖到开发者留下的 `CVar_QAEnableAutoDodge`（QA = 测试），试着通过 `Engine.ini` 的 `[SystemSettings]` 打开，两条通道、所有命名变体、三个探针都试过，无效。

**推测**：cvar 由 C# 层注册，晚于引擎读 ini 的时刻。**另一种可能是那段实现是测试遗留的死代码。**

### 方案三：CSharpLoader + Harmony（你下载的）

**最正确的路线，mod 本身没毛病** —— 加载器正常、`PatchAll` 成功、功能设计合理。

**死在补丁投递不稳定**（见第三节）。

## 五、关于游戏崩溃（**和 mod 无关**）

崩溃历史：

| 时间 | 故障模块 | 异常码 |
|---|---|---|
| **2025/12/15**（3 次，**那时没有任何 mod**） | `crashhandler64.dll` | `0xc0000409` |
| 2026/09/29 20:24–20:28（6 次） | `ucrtbase.dll` | `0xc0000409` |
| 2026/09/29 20:45 → 09/30 00:41（15 次） | `crashhandler64.dll` | `0xc0000409` |

**2025-12-15 那三次是在装任何东西之前**，签名和后面的完全一致（只是 crashhandler64.dll 版本更新导致偏移差一点）。

**结论：你的游戏本身在这台机器上就有玩几分钟崩一次的问题。** 排查方向见下（按性价比）：

1. **内存 XMP/EXPO 或 CPU/GPU 超频** ← UE5 游戏对内存稳定性极敏感，最经典的原因
2. **验证游戏文件完整性**（Steam → 属性 → 已安装文件）
3. **显卡驱动**更新或回滚
4. **虚拟内存**设成系统管理
5. **关掉各种覆盖层**（Steam / Discord / 加速器 / RGB 灯控）
6. **看温度**——如果崩溃时间越来越短，更像热积累

## 六、如果以后还想继续

**优先级从高到低：**

**① 等原 mod 作者更新。** 把两个问题报给他：
- `IsInGame` 单点故障（把 6 个补丁的开关绑在一个 tick 上）
- 配置解析：`config.json` 里 `AlwaysPerfectDodge: true` 与 `AutoDodgeOnAttack: true` 同时写是无效的（第 151 行的 `!AutoDodgeOnAttack` 会让它恒为 false）

**② 找绕过 Harmony 的实现方式。** 比如：
- 游戏自带 `CVar_QAEnableAutoDodge`——如果能找到**运行期**设置 cvar 的办法（游戏内有 GM 控制台 `BGWConsoleCommands`），就完全不需要补丁
- 或者用反射 + 高频轮询自己实现触发（难点是"攻击预警"必须在伤害结算前拿到，轮询拿不到）

**③ 如果只是想用**：启动 → 等 3 分钟 → 看 ADFix 判定 → ❌ 就重开。抽到 ✅ 那次一切正常。

## 七、工具链（都能复用）

| 工具 | 位置 | 用途 |
|---|---|---|
| `ilspycmd` | `~\.dotnet\tools\` | .NET 反编译器 |
| `dnfile` | Python 包 | 解析程序集结构 |
| `csc.exe` | `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\` | 编译 C# mod，1 秒，无需 SDK |
| 反编译产物 | `out\PerfectDodgeSrc\*.cs` | 原 mod 完整源码 965 行 |
| 接口定义 | `out\CSharpModBaseSrc\*.cs` | `ICSharpMod` 接口 |
| ADFix 源码 | `csmod\ADFix\FixMod.cs` | 我写的辅助 mod |

**编译命令：**

```powershell
& 'C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe' `
  /nologo /target:library /platform:x64 /optimize+ `
  /reference:"<游戏>\b1\Binaries\Win64\CSharpLoader\CSharpModBase.dll" `
  /reference:"<游戏>\b1\Binaries\Win64\CSharpLoader\0Harmony.dll" `
  /out:MyMod.dll MyMod.cs
```

丢进 `CSharpLoader\Mods\<名字>\` 即被加载。
